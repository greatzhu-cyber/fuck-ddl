# Privacy Policy

Effective date: 2026-08-09

Fuck DDL is a local-first Windows work recorder. This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it, as described below.

## Data processed by the application

- Tasks, projects, focus sessions, plans, grades, notes, settings and sync metadata are stored locally in the application data directory.
- Pintia/PTA and Zhejiang University course data are read only after the user signs in to the relevant service and starts synchronization. The application does not collect or log those account passwords.
- Source-site cookies and login sessions remain in source-specific browser profiles. They are excluded from JSON backups and cloud business-state synchronization.
- The optional Edge extension reports only the active page hostname and elapsed time to the local Native Messaging host. It does not send full URLs, page titles or page content to the Fuck DDL cloud service.

## Optional network services

- GitHub OAuth is used only when the user chooses to sign in.
- Supabase cloud synchronization is used only after the user signs in and requests synchronization. It transfers versioned Fuck DDL business state for that authenticated user.
- Pintia/PTA and Zhejiang University requests are made to the respective services when the user initiates source synchronization.

Fuck DDL does not include advertising, analytics telemetry or data-broker integrations.

## Storage, deletion and disclosure

Local data remains on the user's device until the user deletes it or uninstalls it together with retained application data. Cloud data can be removed through the application's supported deletion flows or by contacting the maintainer. Data is not sold. It is disclosed only to the service providers selected by the user for the operations described above, or when required by law.

## Third-party services

GitHub, Supabase, Pintia/PTA and Zhejiang University operate under their own privacy policies and terms. Users should review those policies before enabling the corresponding integration.
